# MIT Radiomics Playground

Deterministic pipeline for going from CT volumes to organ segmentations (via [TotalSegmentator](https://github.com/wasserth/TotalSegmentator)) and PyRadiomics feature sets. Includes a batch extraction workflow for the [AutoPET FDG-PET-CT-Lesions dataset](https://wiki.cancerimagingarchive.net/pages/viewpage.action?pageId=93258287) and a statistical analysis pipeline (PCA + Wilcoxon rank-sum) for gender classification from pelvis radiomics.

```
│           ├── PET.nii.gz        # PET volume

│           └── SUV.nii.gz        # Standardized uptake value map

```

## Prerequisites

1. Python 3.11+
2. GPU optional; CPU mode works but is slower for TotalSegmentator
3. Set up the virtual environment:
   ```bash
   python3.11 -m venv mitrpENV
   source mitrpENV/bin/activate
   pip install --upgrade pip
   pip install -r requirements.txt
   ```
   - `TotalSegmentator` pulls in `nnUNetv2` and will prompt to download pretrained weights on first run.
   - Radiomics scripts were validated with PyRadiomics 3.1.0, SimpleITK 2.3.1, NumPy 1.26.4.

## Quickstart: Gender Classification Pipeline

This is the primary workflow. It segments pelvis structures from 30 AutoPET CT scans, extracts radiomics features, and tests for statistically significant differences between male and female subjects.

### Step 1: Activate the virtual environment

```bash
source mitrpENV/bin/activate
```

### Step 2: Run batch feature extraction

```bash
python batch_extract.py
```

This script processes all 30 subjects in `CT/` end-to-end. For each subject it:

1. **Runs TotalSegmentator** to segment the pelvis (hip bones + sacrum):
   ```
   TotalSegmentator -i CT.nii.gz -o segs/ --fast --roi_subset hip_left hip_right sacrum
   ```
   The `--fast` flag uses the 3 mm low-resolution model for speed. The `--roi_subset` flag limits segmentation to only the three pelvis structures, which is significantly faster than segmenting all 104 classes.

2. **Merges the three pelvis masks** (`hip_left.nii.gz`, `hip_right.nii.gz`, `sacrum.nii.gz`) into a single binary mask using a voxel-wise OR operation.

3. **Standardises the CT volume** using functions from `extract_radiomics.py`:
   - **LPS orientation**: Converts the CT and mask to LPS coordinate convention via `sitk.DICOMOrientImageFilter` to ensure consistent spatial alignment across scanners.
   - **HU clamping**: Clamps Hounsfield Units to [-1000, 3000] to remove metal artifact outliers while preserving tissue-level intensity semantics.

4. **Extracts radiomics features** using PyRadiomics with the `ct_config.yaml` configuration:
   - Resamples to 2x2x2 mm isotropic voxels internally
   - Crops to the pelvis bounding box (`preCrop: true`)
   - Discretises at `binWidth: 25` HU (preserves physical HU meaning)
   - Computes 107 features across 7 feature classes: firstorder, shape, GLCM, GLRLM, GLSZM, GLDM, NGTDM
   - Image type: Original only (LoG and Wavelet can be re-enabled in `ct_config.yaml` for more features at the cost of longer runtime)

5. **Merges features with clinical labels** from `CT/First30.csv` (sex, age, diagnosis) and saves the combined dataset to `CT/radiomics_features.csv`.

Runtime: approximately 60-80 seconds per subject (~35-40 minutes total for 30 subjects).

### Step 3: Run PCA + Wilcoxon rank-sum analysis

```bash
python analyze_gender.py
```

This script:

1. Loads `CT/radiomics_features.csv`
2. Drops any constant or NaN features
3. Standardises all features (zero mean, unit variance) using `StandardScaler`
4. Runs **PCA** to reduce dimensionality (default: retain components explaining 95% of variance)
5. Applies the **Wilcoxon rank-sum test** to each principal component, comparing the score distributions of male (n=15) vs female (n=15) subjects
6. Reports a summary table with variance explained, group means, test statistics, and p-values

Optional arguments:
```bash
python analyze_gender.py --input path/to/features.csv   # custom input file
python analyze_gender.py --n-components 10               # fix number of PCs
python analyze_gender.py --alpha 0.01                    # stricter significance level
```

## Single-Subject Feature Extraction

To extract features from a single CT volume with a pre-existing mask (e.g., from TotalSegmentator), use the standalone pipeline:

### Step 1: Segment a CT volume with TotalSegmentator

```bash
TotalSegmentator -i example.nii.gz -o segmentations/
```

Common flags:
- `--roi_subset lung_left lung_right heart`: only segment specific organs (faster)
- `--fast`: use 3 mm low-resolution model (faster, slightly lower fidelity)
- `--ml`: save a single multi-label NIfTI instead of one file per organ
- `--preview`: generate a PNG preview for visual sanity check

### Step 2: Extract radiomics features

```bash
python pyradiomics/extract_radiomics.py \
  --image example.nii.gz \
  --mask segmentations/lung_left.nii.gz \
  --config pyradiomics/pyrads.yaml \
  --outdir outputs/lung_left
```

The 7-step standardisation pipeline in `extract_radiomics.py`:

| Step | What it does | Controlled by |
|------|-------------|---------------|
| 1. Orientation | Convert to LPS coordinates | Hard-coded (LPS) |
| 2. Bias correction | N4 correction for MRI intensity drift | `--bias-correct` flag (MRI only) |
| 3. Intensity | HU clamping for CT; z-score for MRI | `--modality ct/mri`, YAML `normalize` |
| 4. Resampling | Isotropic voxel spacing | `--spacing 1 1 1` |
| 5. Mask policy | Enforce image/mask geometry match | YAML `correctMask`, `preCrop` |
| 6. Discretisation | Fixed bin width (CT) or bin count (MRI) | YAML `binWidth` / `binCount` |
| 7. Version control | Locked software versions | `requirements.txt` |

Additional flags:
- `--bias-correct`: apply N4 bias field correction (MRI only, skip for CT)
- `--modality ct` (default) or `--modality mri`: controls HU clamping vs z-score normalisation
- `--ct-hu-lo` / `--ct-hu-hi`: override the default HU clamp range (default: -1000 to 3000)
- `--spacing 1 1 1`: target voxel spacing in mm (default: 1x1x1 isotropic)

Results are saved to `--outdir` as `features.json` and `features.csv`.

### Minimal example

```bash
python pyradiomics/main.py
```

Runs PyRadiomics with `params.yaml` against `example.nii.gz` and a lung mask for a quick feature dictionary.

## YAML Configuration Files

| Config | Use case | Resampling | Discretisation | Image types |
|--------|----------|-----------|----------------|-------------|
| `ct_config.yaml` | CT batch extraction (pelvis) | 2x2x2 mm | `binWidth: 25` HU | Original |
| `pyrads.yaml` | Production (MRI-optimised) | 1x1x1 mm | `binCount: 64` | Original + LoG + Wavelet |
| `params.yaml` | Basic / quick tests | 1.5x1.5x1.5 mm | `binWidth: 10` | Original + LoG + Wavelet |

To increase the number of extracted features (from ~107 to ~1100+), uncomment the LoG and Wavelet sections in `ct_config.yaml`:

```yaml
imageType:
  Original: {}
  LoG:
    sigma: [1.0, 2.0, 3.0]    # 3 additional filter scales
  Wavelet: {}                   # 8 wavelet decompositions
```

This adds Laplacian of Gaussian (3 scales) and Wavelet (8 decompositions) filtered images, multiplying the feature count by ~12x. Runtime per subject will increase accordingly.

## Working With Your Own Data

- Drop new CT volumes anywhere locally. All `.nii` / `.nii.gz` files except `example.nii(.gz)` are ignored by git, so PHI data stays local.
- Create a labels CSV with columns `Subject ID` and `sex` (plus any other metadata). Update the `LABELS_CSV` path in `batch_extract.py`.
- Edit the `PELVIS_ROIS` list in `batch_extract.py` to target different organs (e.g., `["liver", "spleen", "kidney_left", "kidney_right"]`).
- Update `ct_config.yaml` to change resampling, discretisation, or feature classes.

## Troubleshooting

- **Weights download**: If `TotalSegmentator` cannot find weights on first run, it will prompt you to download them. Ensure you have internet access and sufficient disk space (~1.5 GB).
- **Memory**: Reduce the label set with `--roi_subset`, or use `--fast` to stay within 8 GB GPU / 32 GB RAM limits.
- **PyRadiomics config drift**: Always tie runs to a specific YAML config. Commit the config, not the derived data, to keep experiments reproducible.
- **Multiple scan dates**: Some subjects have multiple study folders. `batch_extract.py` uses the `File Location` column in `First30.csv` to select the correct scan per subject.
